# Gameking


项目简介：Unity C# 实现的卡牌对战 Demo，实现怪兽召唤、祭品召唤、融合召唤、魔法陷阱发动、连锁 / 诱发效果、AI 对手、回合阶段系统 ,对局回放系统；
支持 CSV 配置卡牌数据，数据层与 UI 层解耦。

具体代码在Code中

演示视频与可执行程序在Release中:

https://github.com/lyhbk/GameKing/releases/
> 解压后运行exe即可，无需安装Unity。

系统设计说明:

###  三层架构：数据、中间层、视图


        ┌─────────────────────────────────────────┐
        │  视图层  FightUI / PreEntityCard / RegClick │  只做表现：实例化、位移、动画、弹窗
        └───────────────▲───────────────┬─────────┘
              UI 请求   │               │  Logic 请求（改名/弹窗/等待玩家点选）
        ┌───────────────┴───────────────▼─────────┐
        │  中间层  UILinkLogic（实现 ExternalQuestBase 双向接口）│
        └───────────────▲───────────────┬─────────┘
                        │               │
        ┌───────────────┴───────────────▼─────────┐
        │  数据层  FightLogic / StateMachine / EntityPlayer │  只维护对局数据，不碰 GameObject
        └─────────────────────────────────────────┘
                        ▲
                        │ 解析 CSV 字符串配置，动态构造组件
        ┌───────────────┴─────────────────────────┐
        │  工厂  Factory + CardBase + EffLogic      │
        └─────────────────────────────────────────┘


- **数据层**：只维护「玩家、各区域卡牌、连锁栈、当前阶段与时点」，全程不操作任何 `GameObject`。规则可以脱离 Unity 界面单测。
- **中间层**：`UILinkLogic` 同时实现「UI 调逻辑」与「逻辑调 UI」两套接口，把视图与数据彻底解耦；换 UI 不用改规则，改规则不用碰 UI。
- **视图层**：`FightUI` 只管预制体实例化、移动、弹窗与显示，从不直接修改核心数据。
- **工厂**：`Factory` 把 CSV 里的字符串标记（代价、支付、效果类型）解析成策略对象集合，是「配置驱动」的落地点。

###  状态机与时点：两套概念分开

| 维度 | 取值 | 作用 |
| --- | --- | --- |
| 阶段（Phase） | `DrawCardPhase → PreparePhase → Main1Phase → FightPhase → Main2Phase → EndPhase` | 回合推进的主干流程 |
| 时点（TimePoint） | 自由时点、诱发时点、战斗时点、连锁时点 | 决定「此刻能做什么」，自由时点才可主动发动 |

- **连锁栈**：效果封装为 `EffOrder` 命令对象压栈，**后入先出逆序结算**。
- **结算临界区 `RegionAccessGate`**：FIFO 排队门闩，同一时刻只允许一条效果链在跑，杜绝多异步并发读写场面。
- **诱发分发**：连锁结算完毕 → 广播 `TimePointBase` 时点 → 依次询问玩家是否发动诱发 → 有新效果则重新入连锁。**遍历完必须清空时点集合**，否则会无限弹窗。
- **事件总线 `EventMintor`**：通召、特招、融合、送墓、除外、血量变化等行为以事件广播，触发器监听事件决定是否诱发，把「发生什么」与「因此做什么」解耦。

###  策略模式拆分卡牌效果：Cost → CostPay → Effect

一张卡的效果被拆成三段**生命周期完全不同**的策略：

| 段 | 职责 | 是否修改对局数据 | 失败后果 |
| --- | --- | --- | --- |
| `Cost`（代价判断） | 只判断「能不能发动」：时机对不对、素材够不够、是否被自肃、次数是否用尽 | 只读，绝不写 | 任一返回 false → 整个效果不能发动 |
| `CostPay`（代价支付） | 满足条件后执行消耗：丢手牌、解放怪兽、送墓素材 | 写 | 支付失败 → 不进入效果 |
| `Effect`（效果执行） | 真正结算收益：特招、破坏、除外、抽卡 | 写 | —— |

业务总流程：


卡牌发动触发
   ↓
执行 Cost 策略集合  ——全部 true 才通过（任一 false 直接中止，场面不变）
   ↓
执行 CostPay 策略集合（付出代价，修改对局数据）
   ↓
执行 Effect 策略集合（结算收益）
   ↓
压入连锁栈 → 参与连锁结算 → 广播诱发时点


这套拆法的直接收益：**「效果被无效」时只要不调用 Effect 即可**，`Cost`/`CostPay` 照常执行、代价不回滚——完全贴合实卡规则，不用在一个大函数里用标志位硬掰。

###  配置驱动：CSV + 工厂

`carddata.csv` 每行一张卡，包含基础字段（编号、名称、卡种、攻防、等级、属性、种族、魔法陷阱类型、融合素材…）以及三组**策略标记字段**：

- `cost(cost判断)`：可填多个代价判断标记，如 `JudExist`；
- `costpay`：可填多个代价支付标记，如 `CostCard`；
- `efftype(效果)`：可填多个效果标记，如 `DestoryCard`、`DrawCardEff`；
- `效果数`：声明本卡挂载的效果段数。

`Factory` 据此构造策略对象并组装成集合：**一张卡 = N 个 Cost + N 个 CostPay + N 个 Effect**，因此新增卡牌无需新增脚本类，只在表里填标记组合即可。

### 异步安全：`FightAsyncScope`

卡牌结算本质是「一堆会长期挂起的异步」：等玩家点选、等弹窗关闭、等动画播完。若用写死的 `UniTask.Delay()` 充当节奏，会受帧率与玩家操作速度影响而时序漂移；多路 `async` 同时改场面，还会出现「卡已被移走，逻辑仍持有旧实体」的脏读。

解决方案是**对局级取消作用域**：用一个 `CancellationTokenSource` 贯穿所有停车点（`UniTask.Delay`、UI 的 `tcs` 等待、临界区门闩）。

- 对局开始 `Begin()`：回收上一局遗留 token 源，新建；
- 对局结束 `End()`：全部在途异步在最近一个取消点抛出 `OperationCanceledException` 沿链终止；
- 结束后新起的异步也会在首个取消点自终止，**杜绝「对局已结束但后台仍在推进」**。

###  对象池

`ObjectPool`（`ObjectBool.cs`）以 `Stack<GameObject>` 管理卡牌预制体，墓地 / 除外区 / 弹窗复用同一批实例，避免高频 `Instantiate/Destroy` 产生 GC。

关键细节：`Release()` 会对空引用**和已在池中的对象**早退，否则同一物体被重复入池，`Get()` 时会把同一个 `GameObject` 同时发给两张卡，表现为卡牌 UI 错乱或凭空消失。

###  对局回放：命令式记录与重放

回放没有采用「录视频」或「存帧快照」，而是**记录命令序列**：

- `Record.cs`：对局中按发生顺序追加命令，编号 8 位便于定位——效果类 `1` 开头、支付类 `0` 开头、系统命令（抽卡/阶段切换/攻击/结束）`9` 开头；
- 只记录「发生了什么」以及「只有结算过程中才能知道的数据」（如特招落在第几个怪兽区），这类数据由效果在结算完成后**回补**到对应命令上；不记录「能否发动」「能否连锁」「AI 决策」这类可实时重算的判断结果；
- `RecordPlayer.cs`：`record` 场景由 `fighting` 复制而来，**具备全部 UI 但无对局逻辑**，整局由命令按序驱动，因此回放结果与真实对局一致；支持 `Seek`、单步与节拍间隔（默认 2 秒，可 0～60 秒调节）。

- 卡牌样例数量有限（当前 14 张），规则覆盖以验证引擎骨架为主，尚未覆盖同调 / 超量 / 灵摆等召唤法；

- 回放支持保存到本地文件与分享（当前为局内记录）；
