# Gameking

在CODE栏或查看原始版本中更利于查看

项目简介：Unity C# 实现的卡牌对战 Demo，实现怪兽召唤、祭品召唤、融合召唤、魔法陷阱发动、连锁 / 诱发效果、AI 对手、回合阶段系统；支持 CSV 配置卡牌数据，数据层与 UI 层解耦。


演示视频与可执行程序在Release中:

https://github.com/lyhbk/GameKing/releases/download/v1.0.0/Demo‑Windows.zip
> 解压后运行exe即可，无需安装Unity。


如何操作:
1. 点击【开始游戏】进入战斗对局
2. 主阶段：点击手牌怪兽，点击场上蓝色怪兽格子进行**通常召唤**；高星怪兽需要选择祭品
3. 点击手牌魔法 / 陷阱，点击魔陷格子进行**盖放**
4. 战斗阶段：点击场上怪兽，点击【攻击】按钮，选择攻击目标；直接攻击对方玩家
5. 卡牌满足发动条件，卡牌会亮起发动按钮，可以发动卡牌效果；支持连锁、诱发效果弹窗
6. 点击【下一阶段】推进回合；敌方 AI 会自动执行回合操作

系统设计说明:

分层架构:
1. 数据层 FightLogic：只维护对局数据，不操作任何 GameObject；维护玩家、卡组、场上卡牌、连锁栈、游戏时点
2. 中间层 UILinkLogic：实现双向接口，UI 发起请求调用 Logic，Logic 发起请求调用 UI，解耦视图与数据
3. 视图层 FightUI：只负责预制体实例化、移动、弹窗、显示，不修改游戏核心数据；对象池复用卡牌 UI
4. 实体工厂 Factory：解析 CSV 字符串配置，动态实例化代价、支付、效果组件；不需要硬编码大量卡牌逻辑，配置驱

状态机与时点系统:

回合状态机：DrawCardPhase → PreparePhase → Main1Phase → FightPhase → Main2Phase → EndPhase
四大时点：Freedom自由时点、Target诱发时点、Attack战斗时点、Chain连锁时点
连锁栈：效果压栈，逆序结算；结算临界区RegionAccessGate防止异步并发读写场面数据
诱发系统：游戏事件触发诱发时点，弹窗询问玩家是否发动诱发卡牌   

异步安全机制:
FightAsyncScope 对局级 CancellationTokenSource。切换场景、对局结束时调用End()，所有UniTask.Delay、等待玩家输入全部抛出取消异常，杜绝已经结束对局后台继续执行逻辑。

对象池:
ObjectPool.cs管理卡牌预制体，减少频繁 Instantiate/Destroy 造成 GC；墓地、除外区、弹窗复用卡牌预制体。

策略模式拆分卡牌效果：
  项目中一张卡牌效果完整流程：判断代价 (Cost) → 支付代价 (CostPay) → 执行效果 (Effect)

1. Cost（代价判断策略）：条件校验，判断该效果能不能发动。不修改游戏数据，只做条件返回 bool。
2. CostPay（支付代价策略）：满足代价之后，执行消耗（丢弃手牌、解放怪兽、送墓素材）。
3. Effect（执行效果策略）：真正执行卡牌业务逻辑，特招、破坏、除外、抽卡等。
业务流程总览:
卡牌发动触发
    ↓
执行一组 Cost策略集合（全部返回true，代价才算通过；任意一个false，效果不能发动）
    ↓
全部Cost校验通过 → 执行 CostPay策略集合（执行代价消耗，修改游戏数据）
    ↓
支付代价成功 → 执行 Effect策略集合（执行真正卡牌效果逻辑）
    ↓
送入连锁栈，参与连锁结算、诱发时点广播

优势:

1. 职责单一，逻辑解耦，符合开闭原则

1. Cost：只负责判断 “能不能发动”，不做任何修改游戏数据的操作，只读不写
  判断：时机是否正确？是否满足素材？是否被自肃限制？次数是否用尽？
2. CostPay：只负责 “付出代价”，修改游戏状态（送墓、丢弃、解放），不判断能不能发动，也不写收益逻辑
3. Effect：只负责执行卡牌收益（特招、破坏、抽卡），不关心条件、不关心代价

新增卡牌效果，只需要新增对应的策略类，**不需要修改旧的业务代码**（开闭原则）。


对比一坨 if‑else：每新增一张卡就要修改大函数，越写越乱，极易改崩旧卡牌逻辑。

2. 适配卡牌游戏规则：条件、代价、效果三者生命周期完全不一样

卡牌规则里三者时序严格分开：


① 先全部校验 `Cost` → 全部条件通过；
② 再执行 `CostPay` 支付代价；
③ 最后才执行 `Effect` 效果结算。


重要规则：**代价校验全部通过之后，才支付代价；代价支付完成之后，才执行效果。哪怕代价被处理，效果依然可以被无效。**

无效卡牌：可以**跳过 Effect 执行，但是 CostPay 已经付出的代价不能回滚**。

如果写在同一个函数，遇到 “效果被无效，代价依旧保留” 的规则，逻辑很难拆分；策略拆分后直接 `Cost、CostPay正常执行，不调用Effect` 就完成无效处理。

3. 单元测试友好，可单独测试每一段逻辑

- Cost 策略全部是**只读逻辑**，不需要修改游戏世界状态，可以单独构造对局数据，单元测试各种发动条件是否正确；
- CostPay 可以单独测试 “丢弃手牌、解放怪兽” 代价逻辑；
- Effect 可以单独测试特招、破坏、抽卡的执行结果。
不需要跑完整 Unity 游戏，纯 C# 就可以对条件、支付、效果分别写单元测试。

4. 高度适配配置驱动（你的 CSV+Factory 工厂模式）

策略 + 工厂模式完美配合表格配置：
CSV 填写字符串标记 JudExist、CostCard、DestoryCard，Factory 根据字符串反射 / 分支构造对应的策略对象。

一张卡牌可以挂载多个 Cost、多个 CostPay、多个 Effect。
例：一张卡有 2 个发动条件，2 个要付出的代价，3 段执行效果，直接在表格配置多条，工厂组装成集合。
effection.AddCost(judCost);
effection.AddPay(costPay);
effection.AddEff(eff);

不需要为每张卡新建 C# 脚本，配置表驱动卡牌。

5. 连锁 / 诱发系统灵活复用策略对象

游戏内不同场景可以复用同一套策略：

1. 同样的代价判断JudExist，可以给怪兽效果用，也可以给魔法、陷阱复用；
2. 同样代价CostCard（丢弃一张手牌），几十张卡都可以复用这个策略类；
3. 同样效果DrawCardEff抽卡，多张卡牌直接复用。

如果写硬编码函数，每一张卡复制粘贴代码，重复代码泛滥，改一个规则所有卡牌全部要改。

### 6. 便于拦截、调试、日志埋点

策略都是独立对象，可以统一在调用入口做切面：

- 在执行全部 Cost 前打印日志：输出该卡所有发动条件；
- 每一个 Cost 判断的成功 / 失败可以单独打日志，快速定位为什么卡牌不能发动；
- CostPay 支付代价前后埋日志；Effect 执行前后打印效果行为。

排查 BUG 的时候，可以知道：是条件没过？还是代价支付出错？还是效果执行异常？
如果全部写在一个大函数，很难定位是哪一步出问题。

### 7. 支持动态组合，卡牌逻辑可自由拼装

一张卡牌 = N 个 Cost + N 个 CostPay + N 个 Effect 的组合：
极大减少类数量，不需要为每一张卡牌创建完整独立的 CardEffect 类。

设计难点:
难点 1：卡牌游戏的「时点 + 连锁 + 诱发」异步时序控制

问题现象

卡牌规则时序非常复杂：

1. 效果发动→代价支付→压入连锁栈 → 询问是否连锁；
2. 连锁结算完成后，进入诱发时点，触发墓地 / 场上 / 除外区卡牌的诱发效果；
3. 诱发发动后又会产生新连锁，连锁、诱发可以互相嵌套；
4. 多个异步流程（诱发循环、连锁结算）并发访问场上卡牌数据，出现场面数据读写竞争、重复触发、卡死、逻辑漂移。

最初简单用UniTask.Delay()做延时，延时写死会受帧率、弹窗等待影响，时序不可靠；多个 async 函数同时修改场上卡牌，出现卡牌已经被移走但逻辑还在读取旧实体。

解决方案

1. 状态机 StateMachine：
   - 区分阶段（抽卡 / 主阶段 / 战斗 / 结束） 和时点（自由、诱发、连锁、战斗）**两套概念。
   - 使用orderStack连锁栈，效果封装为EffOrder命令对象，后入先出逆序结算。
2. 实现结算临界区RegionAccessGate，FIFO 排队，同一时刻只允许一条效果链执行，杜绝多异步并发读写场面。
3. 诱发系统：结算完连锁栈后，分发TimePointBase时点，弹窗询问玩家是否发动诱发；诱发发动后再次进入连锁问询循环，支持嵌套。
4. 事件总线EventMintor：通召、特招、送墓、除外、血量变化等行为广播事件，触发器监听事件来执行诱发，逻辑与执行解耦。

> 坑点：诱发循环一定要**及时清空时点集合**，否则会无限循环弹出诱发询问面板。
